# CLAUDE.md

elmdb v2 is an embedded database for Node.js and Electron, written in Rust directly on LMDB (via a narrow `KvStore` / `lmdb-master-sys` FFI substrate — no `heed`, no `hannoy`, no MsgPack). The canonical v2 architecture and algorithm design lives in [`docs/architecture/v2-design.md`](docs/architecture/v2-design.md).

## Layout (6-Layer Crate Topology + `@elmdb/ears`)

| Path | What it is |
|---|---|
| `crates/elmdb-storage` | Layer 0: `KvStore` trait, `CommitReceipt`, `DurabilityGate` (`synced.v2` verified sidecar), `Clock` seam |
| `crates/elmdb-sim` | Layer 0 DST: deterministic in-memory `SimStore` with power-loss/crash-point/fsync fault injection & `SimClock` |
| `crates/elmdb-lmdb` | Layer 0 LMDB: sole `unsafe` FFI wrapper over `lmdb-master-sys` (with macOS `posix-sem`), ping-pong `a`/`b` sub-DB slots, nested savepoints, compacted backup, active meta-page inspection |
| `crates/elmdb-wire` | Layer 1: canonical `CanonicalValue`, unified exact numeric sort keys, `ErrorCode` single source of truth, zero-copy `EWB2` binary batch wire frame codec |
| `crates/elmdb-engine` | Layer 1: `Engine<S: KvStore>`, `SchemaCatalog` with O(1) type/field/relation renames & archived types, `PackedRow` + >4 KiB zstd blob spill, referential integrity (`RESTRICT`/`SET NULL`/`ALLOW DANGLING`), intra-batch `BatchSlot`, bounded `beforeCommit` savepoint hooks, persisted 4,096-commit `commit_log` |
| `crates/elmdb-projections` | Layer 2: unified `Projection` trait & `ProjectionRegistry` — structured value/unique, ICU order, BM25F WAND/block-max text, trigram/fuzzy, materialized rank, `check()` differential equivalence & `rebuild()` |
| `crates/elmdb-vec` | Layer 2: native LMDB-backed HNSW vector index (SQ8/F16/F32) with exact rebuild & background compaction |
| `crates/elmdb-query` | Layer 3: unified algebraic `QueryIr`, cost-aware planner + LRU plan cache, streaming executor, hybrid RRF/linear score fusion, BFS/shortest-path/PPR/Leiden/SCC/topo-sort/Jaccard/Adamic-Adar graph analytics, single-snapshot `ReadSet` dependency capture |
| `crates/elmdb-invalidation` | Layer 3: coarse-to-fine `InvalidationIndex` (Tier 0/1/2 + `CommitRing`), cross-process `commit_log` selective catch-up, sans-I/O `WatchScheduler` with adaptive throttling & 128-bit declarative dedup, `LiveQueryHub` |
| `crates/elmdb` | Layer 4: `#![forbid(unsafe_code)]` high-level `Database` facade, `protocol.rs` (ts-rs & JSON Schema source of truth), lossless atomic `dump`/`load` |
| `crates/elmdb-node` | Layer 5: N-API binding (`elmdb` npm package), zero-dep `elmdb/client` (`WireBatchBuilder`, `BatchSlot`), `protocol/` generated by `cargo xtask generate`, process claim, exit cleanup, panic poisoning |
| `crates/elmdb-cli` | Layer 5: the `elmdb` CLI (`inspect`, `check`, `rebuild`, `backup`, `dump`, `load`, `purge`, `acknowledge-restore`) |
| `packages/ears` | Layer 5: `@elmdb/ears` v2 — zero-dependency fluent TypeScript API (`QueryBuilder`, `BatchWriter`, sans-I/O `WatchPump`, `defineEars` typed facades), browser-safe `.` root + native `./database` entrypoint, API Extractor reports in `etc/` |
| `packages/typescript-floor` | Private workspace holding TypeScript 5.7.3 (oldest supported consumer TS floor verified by `@elmdb/ears` integration tests) |
| `xtask` | Repository tasks (`cargo xtask <task>`): codegen, notices, workspace invariants; never published |
| `package.json` | Root npm workspace tooling (`npm run build`, `typecheck`, `test`, each with `:binding` and `:ears` halves) |

## Checks

While working, run what your change touches:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo xtask check-generated      # protocol TS & schema-2.json match Rust types
cargo xtask check-versions       # Cargo.toml, elmdb, and @elmdb/ears hold one version
cargo xtask check-notices        # THIRD-PARTY-NOTICES matches Cargo.lock
cargo deny check bans sources    # deny.toml: no banned crate, crates.io alone
cargo xtask check-one-lmdb       # exactly one LMDB -sys crate in the dependency tree
cargo xtask check-exact          # ICU & index-defining crates pinned at exact versions
cargo xtask check-sync           # sync primitives match repository policy
cargo xtask check-commits        # LMDB commits stay confined to their single choke point
cargo xtask check-diagnostics-off && cargo xtask check-leiden-serial
npm run build && npm run typecheck && npm test   # binding + @elmdb/ears + TS 5.7 floor integration
npm run api:check -w @elmdb/ears                 # @elmdb/ears API Extractor reports up to date
```

- **Changed a protocol type?** Run `cargo xtask generate` and commit `crates/elmdb-node/protocol/`.
- **Changed a dependency?** Run `cargo deny check bans sources` and `cargo xtask notices`, then commit `crates/elmdb-node/THIRD-PARTY-NOTICES`.
- **Changed `crates/elmdb-node` exports?** Run `npm run build:binding` and commit `crates/elmdb-node/index.d.ts` / `index.js`.
- **Changed `@elmdb/ears` exports?** Run `npm run build:ears && npm run api:update -w @elmdb/ears`, review and commit `packages/ears/etc/*.api.md`.

The toolchain is pinned in `rust-toolchain.toml`, which is also the MSRV.

## Rules

- **Single source of truth & one choke point per invariant:** Rust defines every cross-language contract (`elmdb-wire::ErrorCode`, `crates/elmdb/src/protocol.rs`, `elmdb-wire` EWB2 binary frames). Never hand-write a TS protocol type that Rust generates.
- **Derived state is a pure incremental function of primary state:** Every index is rebuildable from primary state; `check()` proves differential equivalence and `rebuild()` restores it atomically via ping-pong sub-DB slots.
- **Zero `unsafe` outside `crates/elmdb-lmdb` (and minimal N-API boundary if ever needed):** Every `unsafe` block must carry a `// SAFETY:` comment naming the invariant and what upholds it.
- **Zero `any` and zero module-scope mutable state in `@elmdb/ears`:** Enforced by `tests/published-package.integration.spec.ts` and `tests/no-module-state.spec.ts`.
- **Commits:** conventional messages, no attribution lines, one logical change each. Never tag, publish to npm or crates.io, or create releases.
