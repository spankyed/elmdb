# CLAUDE.md

elmdb is an embedded database for Node.js and Electron, written in Rust on LMDB (through heed). The design is in `docs/`:
read `docs/architecture/design.md` before changing anything, and the document that owns the area you are changing (`schema.md`,
`engine.md`, `search.md`, `format.md`, `testing.md`). Active work is in `docs/goals/`.

## Layout

| Path | What it is |
|---|---|
| `crates/elmdb` | the engine and its Rust API |
| `crates/elmdb-node` | the N-API binding, published to npm as `elmdb`; `index.js` and `index.d.ts` are napi-rs's generated loader and declarations, and `protocol/` the protocol's TypeScript, generated by `cargo xtask generate` |
| `crates/elmdb-cli` | the `elmdb` command |
| `xtask` | the repository's own tasks, `cargo xtask <task>`; never published |

## Checks

Run what your change touches, and all of them before a commit that lands an engine change:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace  # each test in its own process, under .config/nextest.toml's deadlines
cargo test --workspace --doc
cargo xtask check-generated      # the protocol's TypeScript matches the Rust types
cargo xtask check-one-lmdb       # exactly one LMDB -sys crate in the dependency tree
npm run build && npm run typecheck && npm test   # the binding, from the root package's tooling
```

- **Changed a protocol type?** `cargo xtask generate`, and commit `crates/elmdb-node/protocol/`.
- **Changed the binding's exports?** `npm run build` regenerates `index.js` and `index.d.ts`;
  commit them. CI fails when they differ from a fresh build.
- CI (`.github/workflows/ci.yml`) runs these on Linux for every push to `main`, and on every target the binding
  ships for on a pull request or a dispatch.

The toolchain is pinned in `rust-toolchain.toml`, which is also the minimum supported Rust version.

## Rules

- **The vocabulary is `design.md`'s, and nothing else**: database, schema, type, field, relation kind, index, plan,
  batch, unit, savepoint, commit, change set, watch, primary, derived. Not core, layer, adapter, plugin or store.
- **Rust is the definition of every cross-language contract.** Never hand-write a TypeScript type the Rust types can
  generate.
- **Errors are `ErrorCode`s**: a new failure takes a new code, and a code never changes meaning. A message says what
  failed and, where there is one, the fix.
- **Every key prefix is declared in the one table in `format`**, marked primary, derived or meta. Derived data must be
  rebuildable from primary data; `check()` proves it.
- **Unsafe code says why it is sound**, in a `// SAFETY:` comment naming the invariant and what upholds it.
- **A comment is for whoever opens the file cold.** It states what the code does and why, never the history of an edit.
- **A test that cannot fail is not a test.** A check is shown failing once, on a mutated copy, when it lands; never
  mutate the working tree to do it.
- **A figure in prose carries its date and conditions**, or names the record or command that derives it.
- **Commits:** conventional messages, no attribution lines, one logical change each. Stage only your own files and read
  `git diff --cached` first. Never tag, publish to npm or crates.io, or create releases.
