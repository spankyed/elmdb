# CLAUDE.md

elmdb is an embedded database for Node.js and Electron, written in Rust on LMDB (through heed). The design is in `docs/`:
read `docs/architecture/design.md` before changing anything, and the document that owns the area you are changing (`schema.md`,
`engine.md`, `search.md`, `format.md`, `filesystems.md`, `testing.md`). `docs/README.md` says what each directory holds.

## Layout

| Path | What it is |
|---|---|
| `crates/elmdb` | the engine and its Rust API |
| `crates/elmdb-node` | the N-API binding, the npm package `elmdb`, which isn't published yet; `index.js` and `index.d.ts` are napi-rs's generated loader and declarations, and `protocol/` the protocol's TypeScript and the schema's JSON Schema, generated by `cargo xtask generate` |
| `crates/elmdb-cli` | the `elmdb` command |
| `xtask` | the repository's own tasks, `cargo xtask <task>`; never published |
| `scripts` | the checks and measurements CI and `pre-push` run that aren't Rust: the mutation gate, the instruction counts, the read profile, the platform checks |
| `package.json` | the tooling that builds, typechecks and tests the binding (`npm run build`, `typecheck`, `test`), kept out of the package it builds |

## Checks

Before a push, run every check CI fails a change on that this machine can run, in one command that stops at the first
failure. It checks what is committed, and refuses a tree with uncommitted changes:

```bash
cargo xtask pre-push              # cheapest first; --base REF when the branch merges into another than origin/main
```

It sweeps the build directories first and refuses to start below 20 GB free (`cargo xtask sweep`, which needs
cargo-sweep; `testing.md`, The build directory). What it can't run is CI's: the other platforms' builds and suites,
the Valgrind readings, the binding loaded unchanged by Node 24 and Electron, and the checks CI makes on its Linux
runner alone: the read-only mount, the idle-reader and reader-recovery scripts, and, where `pre-push` runs off Linux,
the process-claim and publication scripts. A
mutated or scratch copy of the tree builds with `CARGO_TARGET_DIR=$(cargo xtask scratch-target)`.

While working, run what your change touches:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace  # each test in its own process, under .config/nextest.toml's deadlines
cargo test --workspace --doc
cargo xtask check-generated      # the protocol's TypeScript matches the Rust types
cargo xtask check-one-lmdb       # exactly one LMDB -sys crate in the dependency tree
cargo xtask check-icu-exact      # every ICU crate required at exactly its locked version: stored sort keys are stamped with them
cargo xtask check-sync           # engine code locks through crate::sync, which the concurrency models swap, or says why not
cargo xtask check-commits        # a write transaction is committed in store/commits.rs and nowhere else in the engine
cargo xtask check-mutant-exclusions  # every `// mutant-skip:` and exclude_re still names a mutant (needs cargo-mutants)
npm run build && npm run typecheck && npm test   # the binding, from the root package's tooling
cargo xtask check-diagnostics-off && cargo xtask check-leiden-serial  # what the dependency tree may hold
python3 scripts/mutants-in-diff.py BASE  # every mutant of the change caught, BASE what it merges into; fails on a survivor
```

`pre-push` runs more than these: clippy and the engine's suite with the `diagnostics` feature, the heap bound, the
benchmarks' smoke runs, the Loom and Shuttle models, and the read profile. `xtask/src/pre_push.rs`, with the
repository checks `xtask/src/main.rs` hands it, is the list.

- **Changed a protocol type?** `cargo xtask generate`, and commit `crates/elmdb-node/protocol/`.
- **Moved a line a `// mutant-skip:` excuses?** Keep its comment directly above it, and that is all: the comment is the
  exclusion, read from the source at each run, and no list of them is committed. A `cargo mutants` run by hand reads
  them with `--config "$(cargo xtask mutant-exclusions)"`; `.cargo/mutants.toml` holds only exclusions naming no line.
- **A mutant survived?** Kill it with a test that fails on it, or, when no input tells it from the code, name it in a
  `// mutant-skip:` with why. A mutant in code this machine doesn't compile survives whatever the tests: macOS-only code
  is read on a Mac, Linux-only and Windows-only code by CI, which mutates only what each runner compiles. Breaking a line
  by hand checks the cases you thought of; the script checks the ones you didn't, so `pre-push` runs it before the push,
  not after. Code no Rust test can ever reach, such as the binding's exports that only JavaScript calls, is excluded
  once in `.cargo/mutants.toml` rather than skipped mutant by mutant.
- **Stacking a pull request on another?** Run `cargo xtask pre-push` and clear the branch's survivors before branching
  the next from it. A fix made under a stack is merged up through every branch above it, and each push there reruns
  their CI: survivors cleared where the code was written cost minutes, cleared at the end of a stack, hours.
- **Changed the binding's exports?** `npm run build` regenerates `index.js` and `index.d.ts`;
  commit them. CI fails when they differ from a fresh build.
- CI (`.github/workflows/ci.yml`) runs these on Linux for every push to `main`, and for every pull request with the
  fast tier's platforms, Apple silicon and Windows. The full tier (`full.yml`), every other target the binding ships
  for and the Valgrind readings, runs once a pull request is ready for review: marking it ready starts the full tier
  and leaves the fast tier's run alone. Open a pull request as a draft while iterating, mark it ready (`gh pr ready`)
  for the full tier, and merge when the three required checks are green: `ci-pass`, `full-pass`, and `mutants-pass`,
  which a surviving mutant fails.

The toolchain is pinned in `rust-toolchain.toml`, which is also the minimum supported Rust version.

## Rules

- **The vocabulary is `design.md`'s, and nothing else**: database, schema, type, field, relation kind, index, plan,
  batch, unit, savepoint, commit, change set, watch, primary, derived. Not core, layer, adapter, plugin or store
  (`store` names one Rust module, the engine's hold on LMDB, and nothing else).
- **Rust is the definition of every cross-language contract.** Never hand-write a TypeScript type the Rust types can
  generate.
- **Errors are `ErrorCode`s**: a new failure takes a new code, and a code never changes meaning. A message says what
  failed and, where there is one, the fix.
- **Every key prefix is declared in the one table in `format`**, marked primary, derived or meta. Derived data must be
  rebuildable from primary data; `check()` proves it.
- **Unsafe code says why it is sound**, in a `// SAFETY:` comment naming the invariant and what upholds it.
- **A comment is for whoever opens the file cold.** It states what the code does and why, never the history of an edit.
- **A test that cannot fail is not a test.** A check is shown failing once, on a mutated copy, when it lands; never
  mutate the working tree to do it.
- **A figure in prose carries its date and conditions**, or names the record or command that derives it.
- **Commits:** conventional messages, no attribution lines, one logical change each. Stage only your own files and read
  `git diff --cached` first. Never tag, publish to npm or crates.io, or create releases.
